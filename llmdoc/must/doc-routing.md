# Doc Routing

## Read Next By Task
- For `/llmdoc:init` changes: read `llmdoc/architecture/init-investigation-orchestration.md` and `llmdoc/guides/updating-init-investigation-depth.md`.
- For `/llmdoc:team-init` changes: read `commands/team-init.md` and keep `skills/llmdoc-team-init/SKILL.md` mirrored; the base init contract stays in `commands/init.md`.
- For `/llmdoc:update` changes: read `llmdoc/architecture/update-orchestration.md` and `llmdoc/guides/updating-update-workflow.md`.
- For `/llmdoc:review` changes: read `commands/review.md` and keep `skills/llmdoc-review/SKILL.md` mirrored, the same way update keeps its Codex skill aligned.
- For lifecycle, compaction, or Codex hook changes: read `llmdoc/architecture/context-lifecycle.md` and `llmdoc/guides/updating-lifecycle-hooks.md`.
- For public interface or repo layout changes: read `llmdoc/overview/project-overview.md` and `llmdoc/reference/repo-surfaces.md`.
- For repeated workflow mistakes or regressions: check `llmdoc/memory/doc-gaps.md` for a matching open gap, then the relevant guide.

## Escalation Hints
- If the question is about why a workflow exists, prefer `overview/` and `architecture/`.
- If the question is about how to execute a recurring maintenance task, prefer `guides/`.
- If the question is about stable filenames, commands, or config surfaces, prefer `reference/`.
